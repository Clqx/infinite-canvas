# Docker 部署

如果你希望在自己的机器或服务器上运行项目，可以直接使用 Docker Compose。主应用镜像默认启用 Nginx 单用户入口鉴权并只绑定宿主机 `127.0.0.1`，所有静态资源和单页应用深层路由都会受到保护；缺少有效凭据时容器会拒绝启动。

## 使用发布镜像

```bash
git clone git@github.com:basketikun/infinite-canvas.git
cd infinite-canvas
export AUTH_USERNAME=canvas
export AUTH_PASSWORD="$(openssl rand -base64 24)"
docker compose up -d
```

启动后访问：

```text
http://localhost:3000
```

浏览器会显示 HTTP Basic Auth 登录框。`AUTH_USERNAME` 必须为 1–64 个 ASCII 字母、数字、点、下划线或连字符，且以字母或数字开头；`AUTH_PASSWORD` 必须为 12–72 字节。bcrypt 最多安全处理 72 字节，因此更长密码会被拒绝，而不是被静默截断。

也可以复制 `.env.example` 为 `.env` 后填写这两个值。默认 `IMAGE_NAME` 指向当前 `Clqx/infinite-canvas` fork 的镜像；使用其他 fork 时应改为对应的 GHCR 包和不可变版本 tag。不要提交 `.env`，也不要使用示例或公开密码。

## 使用密码文件

在共享主机或长期部署中，推荐通过只读文件提供密码，避免把密码留在容器进程环境中：

```bash
umask 077
openssl rand -base64 24 > ../infinite-canvas-auth-password

docker run -d --name infinite-canvas \
  -p 3000:3000 \
  -e AUTH_MODE=required \
  -e AUTH_USERNAME=canvas \
  -e AUTH_PASSWORD_FILE=/run/secrets/infinite-canvas-password \
  --mount type=bind,src="$(realpath ../infinite-canvas-auth-password)",dst=/run/secrets/infinite-canvas-password,readonly \
  ghcr.io/clqx/infinite-canvas:latest
```

`AUTH_PASSWORD` 与 `AUTH_PASSWORD_FILE` 只能设置一个。密码文件可以带一个结尾换行，但不能包含多行内容。容器只把 bcrypt hash 写入内部 `htpasswd`，不会把明文写进生成的网页配置或访问日志。

<Callout type="warn">
HTTP Basic Auth 只编码凭据，不负责传输加密。需要通过局域网以外的网络访问时，必须在容器前配置 HTTPS 反向代理；不要直接把 3000 端口暴露到公网。
</Callout>

默认 Compose 只发布到 `127.0.0.1:3000`，适合由同一宿主机上的 HTTPS 反向代理访问。只有确认 TLS 入口已经就绪时，才可在 `.env` 中显式设置 `APP_BIND_ADDRESS=0.0.0.0`；不要直接通过明文 HTTP 公开该端口。

镜像会发送限制脚本来源的 CSP、`no-store`、`nosniff`、禁止嵌入和 HSTS 等响应头。HSTS 只有经 HTTPS 访问时才会被浏览器采用，因此它不能替代反向代理的 TLS 配置。

## 本地构建镜像

如果需要基于当前源码构建镜像：

```bash
docker compose -f docker-compose.local.yml up -d --build
```

该本地 Compose 明确设置 `AUTH_MODE=disabled`，同时只把端口绑定到 `127.0.0.1`。镜像还要求 `AUTH_ALLOW_INSECURE_LOOPBACK=1` 才允许关闭鉴权；这个开关只是防误用，容器无法自行验证宿主机的端口发布范围，因此不要把禁用模式复制到其他 Compose 或公网部署。

## 文档站镜像

文档站位于 `docs/` 目录，按带服务端能力的 Next.js standalone 应用单独构建，不打进主应用镜像。

使用发布镜像：

```bash
cd docs
docker compose up -d
```

基于当前源码本地构建：

```bash
cd docs
docker compose -f docker-compose.local.yml up -d --build
```

## 数据说明

当前主应用镜像只启动 Nginx 静态站点。画布、我的素材和生成记录保存在浏览器本地；AI、WebDAV 和 Agent 凭据在首次使用时由本地密码加密后独立存储。第三方提示词由浏览器前端直连拉取，不需要额外挂载数据目录。启用或轮换入口密码不会改变站点 origin，也不会迁移或删除这些浏览器数据。

## 统计分析（可选）

项目**默认不接入任何统计**：不设置下列环境变量时，页面不会加载任何统计脚本，也不会发送任何外部请求。你在自己的部署上想查看流量时，设置对应环境变量即可，无需修改代码或重新构建镜像——镜像启动时会据此生成运行期配置。

统计按「每家一个独立变量」配置：**填了谁就启用谁，可同时启用多家**（例如 GA4 + 百度一起开）。仅支持 GA4 与百度，两者都只接受 ID，脚本地址由代码固定拼接，不接受任意脚本地址或内联 JS。

| 变量 | 说明 |
| --- | --- |
| `ANALYTICS_GA4_ID` | Google Analytics 4 衡量 ID（`G-XXXX`） |
| `ANALYTICS_BAIDU_ID` | 百度统计站点 ID（`hm.js?` 后面那串 hash） |

在 `docker-compose.yml` 的 `environment` 中配置（文件内已附注释示例），下例同时启用 GA4 与百度：

```yaml
services:
  app:
    image: ghcr.io/clqx/infinite-canvas:latest
    ports:
      - "3000:3000"
    environment:
      AUTH_MODE: required
      AUTH_USERNAME: canvas
      AUTH_PASSWORD: 请换成随机生成的密码
      ANALYTICS_GA4_ID: G-XXXXXXXXXX
      ANALYTICS_BAIDU_ID: e8263761cc5c32f5f7a855b8203b965a
```

或使用 `docker run`：

```bash
docker run -d -p 3000:3000 \
  -e AUTH_MODE=required \
  -e AUTH_USERNAME=canvas \
  -e AUTH_PASSWORD="$(openssl rand -base64 24)" \
  -e ANALYTICS_GA4_ID=G-XXXXXXXXXX \
  -e ANALYTICS_BAIDU_ID=e8263761cc5c32f5f7a855b8203b965a \
  ghcr.io/clqx/infinite-canvas:latest
```

单页应用的路由切换会自动向所有已启用的统计上报 pageview。

<Callout type="warn">
请只在你自己的站点上配置统计 ID，不要把 ID 提交进仓库；fork 或自托管本项目的用户默认不会产生任何统计。
</Callout>
