# 身份与 JWT 接入规划

## 当前模式

当前版本使用浏览器本地用户档案：首位用户自动成为管理员，管理员通过一次性激活码创建后续用户、分配本机角色并停用账号。激活码只保存摘要，使用后立即失效；用户档案写入带逻辑版本并在支持 Web Locks 的浏览器中串行执行，账号停用和角色变化会同步到已打开的标签页。

本机角色只用于当前浏览器中的界面和数据分区，不能作为跨设备或商业多租户的授权依据。浏览器持有并可修改前端代码与本地存储，因此商业部署必须由同源服务端确认身份、租户和角色，并在每个数据接口重新执行授权校验。

## 托管身份模式

商业部署增加同源身份服务后，前端统一读取以下会话，不直接解析或信任外部 JWT 中的角色：

```ts
type ManagedSession = {
  user: {
    id: string;
    subject: string;
    username: string;
    displayName: string;
    roles: Array<"admin" | "user">;
    tenantId: string;
    identityProvider: string;
  };
  expiresAt: string;
};
```

- `GET /api/auth/session`：返回当前已验证会话；未登录返回 `401`。
- `POST /api/auth/exchange`：优先接收外部网站签发的一次性授权码并在服务端交换身份；必须兼容 JWT 时，只接收短时、单用途令牌，验证后建立本站 `HttpOnly`、`Secure`、`SameSite` 会话。
- `POST /api/auth/logout`：撤销本站会话。
- `GET /api/admin/users`：管理员读取当前租户用户。
- `POST /api/admin/users`：管理员邀请或创建当前租户用户。
- `PATCH /api/admin/users/:id`：管理员调整角色或账号状态。

## 令牌与会话要求

- 身份服务按精确配置的 `issuer`、`audience`、允许算法、公钥集合、`exp`、`nbf`、`iat` 和 `sub` 验证外部 JWT，不根据令牌内容动态选择签发方或算法。
- 一次性交换凭证使用后立即作废；JWT 交换通过 `jti` 去重或等效机制拒绝重复使用，并限制很短的有效期。
- 外部角色必须经过服务端白名单映射再转换为本站角色；未映射角色默认不获得管理员权限，前端传入的角色、本地档案角色和租户标识一律不作为授权依据。
- 只允许配置中的精确来源访问交换接口，CORS 不使用通配来源；基于 Cookie 的状态变更接口同时校验 `Origin` 或 `Referer` 并使用 CSRF 令牌。
- 登录和权限提升后轮换会话标识。退出、密码变更、账号停用、角色变更和管理员主动撤销后，服务端会话立即失效，不能只等待 Cookie 到期。
- 会话记录保存创建时间、最近使用时间、过期时间、用户、租户和撤销状态；支持按单会话、用户及租户撤销，并设置空闲与绝对有效期。
- 签发方公钥按 `kid` 缓存并支持密钥轮换；刷新失败时只在受控短时间内使用仍有效的已知密钥，未知密钥或过期缓存必须拒绝交换。
- 令牌不进入 URL、浏览器持久化存储、分析事件或应用日志。交换接口设置请求频率限制，并记录不含凭证原文的成功、失败、撤销和管理员变更审计事件。

## 数据边界

托管模式下，浏览器本地用户名不再决定租户身份。服务端返回的内部 `user.id` 和 `tenantId` 共同确定数据范围，所有管理、画布、素材、媒体及同步接口均在服务端校验租户和角色。媒体使用不可由客户端覆盖的租户前缀对象存储路径，数据库访问通过统一数据层强制加入租户条件，后台任务也携带经过服务端确认的租户上下文。

## 实施顺序

1. 增加身份服务与会话接口，并支持本地模式和托管模式显式切换。
2. 将管理员用户管理迁移到服务端接口，前端本地管理仅保留给单机部署。
3. 将画布、素材和媒体元数据迁移到带租户边界的服务端存储。
4. 对接外部身份签发方，完成一次性交换、账号绑定、角色映射、密钥轮换、退出和会话撤销。
5. 增加交换凭证重复使用、来源校验、CSRF、租户权限、账号停用、管理员变更、会话撤销和数据导出相关的集成测试。
